# 技术架构

Regis Oracle 按输入、研究、约束和展示划分职责。公共版先开放现有组件源码，逐步建立独立的示例、数据契约和测试覆盖。

~~~mermaid
flowchart TD
    A["自己的合法数据 / 离线虚构夹具"] --> B["factor_system.data 与来源检查"]
    B --> C["operators / preprocess / templates"]
    C --> D["metrics / validate / registry"]
    D --> E["compose / backtest"]
    Q["quantqc：规则、费用、统计"] --> D
    Q --> E
    E --> R["研究结果与证据状态"]
    R --> U["mom_trading 桌面工作台原型"]
    T["trade_assistant 行情与决策组件"] --> U
~~~

## 组件

| 目录 | 作用 | 边界 |
| --- | --- | --- |
| factor_system | 算子、特征模板、搜索编排、质量检查、注册及回测 | 模板与候选不是已通过的因子 |
| quantqc | 费用、统计、证券代码和 A 股规则工具 | 规则参数需匹配研究日期与真实账户权限 |
| research/backtest_project/backtest_engine | 组合、执行、风险、数据与策略研究引擎 | 数据与历史结果未包含 |
| research 其他工具 | 专项研究、输入和审计工具的源码 | 部分依赖内部旧协议，公共运行支持逐项补齐 |
| mom_trading | Flask 研究页面及 API | 页面/路由存在不等于输入、信号或部署就绪 |
| trade_assistant | 行情适配、风险和人工决策支持 | 不负责券商下单，不提供已认证交易建议 |

## 状态与复现

数据文件、运行目录、登记数据库和实验结果在 Git 外保存。研究记录应引用版本、输入哈希、可见时点和验证协议。运行自己的实验时，保留失败与累计试验数量；不要将研发路径直接依赖公共仓库中不存在的历史文件。

## 公开发布边界

公共版有独立的 Git 历史。内部交接、机器配置、历史合同、行情缓存、研报与账户均未随版本发布。公开仓库的内容与测试决定本版本支持范围；未公开材料不构成公众可复核的证据。
