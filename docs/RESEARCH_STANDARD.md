# 研究与验证标准

## 冻结研究问题

先描述机制、公式、输入可见时间、交易规则、预期市场状态与失败条件。登记数据版本、试验上限、主比较、成本假设和停止条件，再看结果。

## 分开处理证据

| 层级 | 回答的问题 |
| --- | --- |
| 工程验证 | 在指定输入下代码行为是否正确、可复现？ |
| 数据验证 | 数据的权利、覆盖、时点与单位是否满足研究问题？ |
| 历史验证 | 累计试验受控时，在独立时序区间是否仍有增量？ |
| 执行验证 | 整手、资金、T+1、停牌、价格限制、容量与成本如何影响结果？ |
| 前向观察 | 在冻结规则后，实际提示、人工响应、取消与未成交能否记录？ |

不能用测试通过、注册记录、协议文件或漂亮的回测曲线跳过这些问题。

## 防止事后选择

所有候选、变体、状态、阈值和失败家族应计入研究台账。事后发现“某状态有效”属于探索，需要冻结新协议并在独立时间验证。已反复查看的区间不能再次叫作未触碰样本外。

## 小资金研究

基线示例可采用 15 万元模拟资金，主比较使用可执行宽基 ETF；两臂保持相同资金、权限、人工延迟与成本。股票研究持仓以 1–5 日为目标，代码中的通用默认参数不自动满足该协议，应在实验中显式指定。

低迷状态默认减少风险或不新增交易。市场与板块状态分别建模；不要用单一温度计替代全部交易条件。历史费用/交易规则必须匹配对应日期，触价不代表实际成交。

## 结果报告

每个候选给出通过、淘汰或证据不足，并保留公式、数据、全部尝试、净结果、适用状态和限制。公开版首发没有已获实盘准入的因子或策略。收益、回撤与可交易性依赖具体数据和验证，不能从软件功能推导。
